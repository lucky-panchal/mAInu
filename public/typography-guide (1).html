Typography system

A type scale built for product websites

A reference for choosing and sizing fonts across a product site — marketing pages, dashboards, and everything between. Built so a developer can implement it directly from the CSS variables below.

The type scale

Six roles cover almost every product page. Each has a fixed size, weight, and job — resist adding more.

Display
56–72px · 700–800 · 1.05 line-height
Hero headline
Landing page hero only. One per page.
H1 / Page title
36–44px · 700 · 1.15 line-height
Section heading
Page titles, section headers, dashboard titles.
H2 / Subhead
24–28px · 600 · 1.25 line-height
Subsection heading
Card titles, feature headers, modal titles.
Body
16–17px · 400 · 1.6 line-height
Paragraph and description text, kept under 80 characters per line for comfortable reading.
Paragraphs, descriptions, form helper text.
UI label
14px · 500–600 · 1.4 line-height
Button, nav, and form labels
Buttons, nav items, input labels, tabs.
Caption / Meta
12–13px · 400–500 · 1.4 line-height
Timestamps, footnotes, table meta
Timestamps, table headers, footnotes, badges.

Font pairings by product type

Each pairing below uses a different family combination — none repeats across categories, so picking one won't make your product look like the next one over.

SaaS / product dashboard
Sora + Public Sans
Sora's soft geometry gives headings a modern, confident edge; Public Sans stays plain and dense-friendly for the interface underneath.
Headings: Sora 600/700 · Body/UI: Public Sans 400/500
Editorial / content platform
Literata + Work Sans
A scholarly, book-like serif for headlines and article titles, set against a humanist sans tuned for small-size legibility in nav and UI.
Headings: Literata 600 · Body/UI: Work Sans 400/500
E-commerce / consumer brand
Fraunces + Figtree
Fraunces brings warmth and character to hero and category headers; Figtree's rounded geometry keeps prices, specs, and checkout friendly and legible.
Headings: Fraunces 600 · Body/UI: Figtree 400/500
B2B / enterprise / fintech
IBM Plex Sans + Plex Mono
A technical, trustworthy sans built for interfaces, with its matching mono for data, code, and figures — signals precision without feeling cold.
Headings/Body: IBM Plex Sans · Data: IBM Plex Mono
Creative agency / portfolio
Space Grotesk + DM Sans
Space Grotesk's technical quirk makes headlines feel deliberate and studio-made; DM Sans keeps supporting copy quiet and out of the way.
Headings: Space Grotesk 600/700 · Body/UI: DM Sans 400/500
Healthcare / professional services
Newsreader + Karla
Newsreader's refined italics lend trust and calm to headlines; Karla, a clean humanist sans, keeps forms and instructions approachable.
Headings: Newsreader 500/600 italic accents · Body/UI: Karla 400/500

CSS for developers

Drop these tokens in and reference them everywhere instead of hard-coding sizes. Swap the two family values for whichever pairing above fits your product — nothing else needs to change.

:root {
  /* Swap these two lines for your chosen pairing, e.g. Sora + Public Sans */
  --font-heading: 'Sora', system-ui, sans-serif;
  --font-body: 'Public Sans', system-ui, sans-serif;
  --font-mono: 'IBM Plex Mono', ui-monospace, monospace;

  /* Type scale — stays the same regardless of pairing */
  --text-display: 700 clamp(2.5rem, 5vw, 4.5rem)/1.05 var(--font-heading);
  --text-h1:      700 clamp(1.75rem, 3vw, 2.75rem)/1.15 var(--font-heading);
  --text-h2:      600 1.5rem/1.25 var(--font-heading);
  --text-body:    400 1rem/1.6 var(--font-body);
  --text-ui:      500 0.875rem/1.4 var(--font-body);
  --text-caption: 500 0.8125rem/1.4 var(--font-body);
}

h1 { font: var(--text-h1); }
h2 { font: var(--text-h2); }
p, li { font: var(--text-body); max-width: 65ch; }
button, .nav-link, label { font: var(--text-ui); }
.caption, time, .table-meta { font: var(--text-caption); color: var(--ink-soft); }
code, .price, .data-cell { font-family: var(--font-mono); }

Ground rules

  • Use one or two font families total — a third almost always looks accidental.
  • Never go below 16px for paragraph text; smaller reads as an accessibility miss, not a stylistic choice.
  • Keep body line length under 80 characters; serif body text can run slightly longer with a touch more line-height.
  • Reserve bold weights (700+) for headings and CTAs only — bolding body text for emphasis fatigues the eye.
  • Load fonts via <link> or self-hosted @font-face, not client-side JS injection, to avoid layout shift.
  • Set a system-font fallback stack on every family so text never disappears during load.
